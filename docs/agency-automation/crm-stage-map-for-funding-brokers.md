# CRM Stage Map for Funding Brokers

A practical CRM stage map for funding brokers, ISOs, referral partners, broker VAs, processors, and agency owners who need cleaner pipeline visibility, better borrower follow-up, tighter document collection, and fewer “where did that deal go?” moments.

This file is designed to help you organize funding leads from first contact through document collection, lender submission, offer review, funding, nurture, or disqualification.

## How to Use This File

Use this file as a build sheet for your CRM, spreadsheet pipeline, Notion database, Airtable base, GoHighLevel board, HubSpot pipeline, Close CRM setup, ClickUp workspace, or whatever chaos container currently holds your deals.

Recommended workflow:

1. Add the CRM stages below in the same order.
2. Create the recommended CRM fields.
3. Assign an owner for each stage.
4. Define the next action before a file can move forward.
5. Automate reminders and admin work where safe.
6. Keep funding fit, offer explanations, borrower-sensitive communication, and lender communication under human review.
7. Audit the pipeline weekly.

Broker automation doctrine:

> Automate the admin.  
> Assist the analysis.  
> Human-review the money talk.  
> Audit everything.

## CRM Stage Operating Rules

Before using the stage map, set these rules:

| Rule | Why It Matters |
|---|---|
| Every deal needs a CRM stage | No mystery files. No ghost deals. |
| Every deal needs a next action | A deal without a next action is a parked car with no wheels. |
| Every deal needs an owner | Someone must be responsible for movement. |
| Every borrower-facing message needs compliance awareness | No approval promises, fake urgency, or careless claims. |
| Every lender submission needs human review | AI can help organize. It should not make the money call. |
| Every automation needs an audit trail | If the robot touches the pipeline, you need receipts. |

## Recommended CRM Stages

### 1. New Lead

| Field | Details |
|---|---|
| Stage definition | A new business owner, borrower, or referral has entered the pipeline but has not yet been contacted. |
| Entry criteria | Lead form submitted, referral received, inbound call logged, ad lead captured, partner referral added, or manual lead entered. |
| Exit criteria | First contact attempt completed and logged. |
| Owner | Intake rep, broker, VA, or assigned pipeline owner. |
| Next action | Contact the lead by phone, SMS, and/or email using approved outreach language. |
| Automation opportunities | Create CRM record, assign owner, send internal alert, send confirmation email, tag lead source, create first follow-up task. |
| Human review required | Review lead source quality, duplicate records, sensitive notes, and whether outreach should proceed. |
| Common failure point | Lead sits untouched because no owner or first action was assigned. |

**Recommended automation:** When a new lead form is submitted, create the CRM record, notify the broker, and create a same-day contact task.

---

### 2. Contact Attempted

| Field | Details |
|---|---|
| Stage definition | The team has attempted contact, but the borrower has not yet engaged in a meaningful conversation. |
| Entry criteria | First call, SMS, email, or DM attempt completed and logged. |
| Exit criteria | Borrower responds, books a call, completes intake, or fails to respond after defined attempts. |
| Owner | Broker, intake rep, or VA. |
| Next action | Continue follow-up sequence until connected, booked, lost, or moved to nurture. |
| Automation opportunities | Follow-up reminders, SMS/email sequence, missed-call text, calendar booking link, call attempt logging. |
| Human review required | Review tone, claims, and escalation language. Do not imply preapproval or guaranteed eligibility. |
| Common failure point | One sad little text gets sent, then everyone acts shocked when the borrower disappears. |

**Recommended automation:** Trigger a three-to-five touch follow-up sequence over several days with stop conditions when the borrower replies.

---

### 3. Connected

| Field | Details |
|---|---|
| Stage definition | Borrower has responded or completed a meaningful conversation, but funding readiness has not yet been reviewed. |
| Entry criteria | Borrower replies, books a call, answers intake questions, or confirms interest. |
| Exit criteria | Basic pre-screen completed or borrower is moved to not ready, nurture, or do not pursue. |
| Owner | Broker or intake rep. |
| Next action | Collect basic borrower profile, funding request, revenue, time in business, use of funds, and document status. |
| Automation opportunities | Send intake form, create borrower profile fields, summarize call notes, update last contact date. |
| Human review required | Review borrower statements, urgency, use of funds, and sensitive financial context. |
| Common failure point | Broker has a good call but fails to capture structured data. Vibes are not a CRM field. |

**Recommended automation:** After a call, use AI to draft an intake summary for human review before it is saved to the borrower profile.

---

### 4. Pre-Screened

| Field | Details |
|---|---|
| Stage definition | Basic borrower profile has been reviewed to determine whether the file may be worth progressing. |
| Entry criteria | Key intake fields collected: time in business, monthly revenue, funding requested, use of funds, credit range, industry, and current document status. |
| Exit criteria | Docs requested, moved to not ready, moved to nurture, or marked do not pursue. |
| Owner | Broker or senior intake reviewer. |
| Next action | Decide whether to request documents, clarify missing info, or stop active pursuit. |
| Automation opportunities | AI intake summary, missing data checklist, preliminary document request, CRM tag updates. |
| Human review required | Broker judgment required. AI may assist analysis but should not determine approval, eligibility, or final lender fit. |
| Common failure point | Team requests documents before confirming basic fit, creating busywork and borrower friction. |

**Recommended automation:** Generate a “missing intake info” checklist before requesting full documents.

---

### 5. Docs Requested

| Field | Details |
|---|---|
| Stage definition | Borrower has been asked to provide documents or complete a bank link required for review. |
| Entry criteria | Broker or processor sends document checklist or secure upload/bank-link instructions. |
| Exit criteria | Documents partially received, file complete, borrower stalls, or moved to nurture. |
| Owner | Processor, broker VA, or broker. |
| Next action | Confirm exactly what is needed and send borrower-friendly instructions. |
| Automation opportunities | Send document checklist, create missing document tasks, trigger reminders, update file status. |
| Human review required | Review whether the requested documents are appropriate for the product path and current lender requirements. |
| Common failure point | Borrower gets a vague “send docs” message and vanishes into the fog. |

**Recommended automation:** Send a document request message with a checklist, secure upload instructions, and a clear next step.

---

### 6. Docs Partially Received

| Field | Details |
|---|---|
| Stage definition | Borrower has submitted some documents, but the file is not complete enough for review or submission. |
| Entry criteria | At least one requested document has been received or bank link is partially completed. |
| Exit criteria | Missing documents received, file complete, borrower stalls, or moved to nurture. |
| Owner | Processor, broker VA, or broker. |
| Next action | Identify missing documents and send a specific follow-up. |
| Automation opportunities | Missing document reminders, CRM missing-doc field updates, internal alerts, borrower checklist refresh. |
| Human review required | Confirm document quality, relevance, completeness, and whether sensitive information is handled properly. |
| Common failure point | Team says “still need docs” instead of naming exactly what is missing. Specific beats spooky. |

**Recommended automation:** When missing document fields are updated, trigger a personalized reminder listing only the missing items.

---

### 7. File Complete

| Field | Details |
|---|---|
| Stage definition | Required intake information and documents appear complete enough for broker/lender submission review. |
| Entry criteria | Core borrower profile, funding request, use of funds, bank statements or bank link, ID, and relevant documents are received based on the product path. |
| Exit criteria | File submitted to lender, held for broker review, or returned to borrower for corrections. |
| Owner | Broker, processor, or submission manager. |
| Next action | Generate internal deal summary and complete human review before submission. |
| Automation opportunities | Deal summary draft, document checklist validation, internal submission prep alert, file-complete timestamp. |
| Human review required | Required. Broker must review all key details before any lender submission. |
| Common failure point | File is marked complete even though key fields are missing or documents are outdated. Garbage in, lender side-eye out. |

**Recommended automation:** Create a deal summary draft and a human review checklist when the file status changes to complete.

---

### 8. Submitted to Lender

| Field | Details |
|---|---|
| Stage definition | File has been submitted to one or more lenders, platforms, or funding partners for review. |
| Entry criteria | Broker-approved submission package sent or uploaded to lender/partner portal. |
| Exit criteria | Lender requests more information, offers received, declined, withdrawn, or no response after follow-up. |
| Owner | Broker or submission manager. |
| Next action | Track lender status, follow up on conditions, and update borrower appropriately. |
| Automation opportunities | Lender status tracker, submission timestamp, follow-up reminders, internal task creation. |
| Human review required | Required for lender communication, borrower status updates, and any discussion of likely outcomes. |
| Common failure point | Broker submits the file and forgets to track where it went. That is not pipeline management; that is throwing papers into the ocean. |

**Recommended automation:** Log each lender submitted to, date submitted, status, requested conditions, and next lender follow-up date.

---

### 9. Offers Received

| Field | Details |
|---|---|
| Stage definition | One or more potential funding offers, term sheets, approvals, proposals, or lender options have been received. |
| Entry criteria | Lender or funding partner provides offer details or conditional terms. |
| Exit criteria | Offer reviewed with borrower, offer declined, additional offers pending, or moved to not ready/nurture. |
| Owner | Broker or senior broker. |
| Next action | Review offer details internally before borrower-facing explanation. |
| Automation opportunities | Offer tracking fields, comparison table draft, internal review task, borrower meeting reminder. |
| Human review required | Required. AI should not explain terms without broker review. Terms may change and lender review controls. |
| Common failure point | Broker forwards offer details without explaining tradeoffs, risks, conditions, or next steps carefully. |

**Recommended automation:** Create an internal offer comparison draft, then require human approval before any borrower-facing version is sent.

---

### 10. Offer Reviewed

| Field | Details |
|---|---|
| Stage definition | Broker has reviewed the offer with the borrower or decision-maker. |
| Entry criteria | Borrower has received a human-reviewed explanation of available offer details and next steps. |
| Exit criteria | Borrower accepts, declines, requests more options, stalls, or is moved to nurture. |
| Owner | Broker. |
| Next action | Confirm borrower decision and collect any additional required conditions. |
| Automation opportunities | Meeting recap, task list for conditions, reminder sequence, accepted/declined status update. |
| Human review required | Required. Any offer discussion, repayment explanation, risk discussion, or comparison must be handled carefully. |
| Common failure point | Borrower hears numbers but does not understand conditions, fees, timing, or obligations. Confusion is where deals go to die. |

**Recommended automation:** After the review call, generate a broker-reviewed recap with next steps and no unsupported promises.

---

### 11. Funded

| Field | Details |
|---|---|
| Stage definition | Borrower has accepted funding and funding has been completed or confirmed. |
| Entry criteria | Funding confirmation received from lender, platform, or borrower. |
| Exit criteria | Moved into renewal tracking, post-funding service, referral request, or long-term nurture. |
| Owner | Broker, account manager, or retention owner. |
| Next action | Confirm funding, update referral partner if applicable, record funding data, and schedule renewal or check-in reminders. |
| Automation opportunities | Funded notification, referral partner update, renewal reminder, review request, post-funding check-in task. |
| Human review required | Review funded amount, commission data, borrower communication, and any post-funding obligations. |
| Common failure point | Broker celebrates the win and forgets retention, referrals, renewals, and recordkeeping. Rookie tax. |

**Recommended automation:** Trigger 30/60/90-day check-ins and renewal reminders based on product type and lender rules.

---

### 12. Not Ready

| Field | Details |
|---|---|
| Stage definition | Borrower may not be ready for active funding review based on missing requirements, weak profile, incomplete documents, timing, or other issues. |
| Entry criteria | Broker review finds borrower may need more revenue history, cleaner statements, more time in business, better documentation, or other improvements. |
| Exit criteria | Borrower improves readiness, enters nurture, becomes eligible for another option, or is marked do not pursue. |
| Owner | Broker or nurture owner. |
| Next action | Give a clear, careful explanation of what may need to improve and set a follow-up date if appropriate. |
| Automation opportunities | Readiness checklist, nurture sequence, future follow-up task, educational resource delivery. |
| Human review required | Required. Avoid making legal, credit, tax, accounting, underwriting, or approval claims. |
| Common failure point | Broker gives vague rejection language instead of useful next steps. “Come back later” is not a strategy. |

**Recommended automation:** Assign a readiness category and trigger an educational follow-up sequence with human-approved language.

---

### 13. Lost / Nurture

| Field | Details |
|---|---|
| Stage definition | Borrower did not move forward now, but may be worth future follow-up. |
| Entry criteria | Borrower stops responding, declines current options, delays timing, or needs future readiness work. |
| Exit criteria | Borrower re-engages, becomes ready, requests new review, unsubscribes, or is marked do not pursue. |
| Owner | Broker, VA, or nurture owner. |
| Next action | Add to nurture sequence with appropriate follow-up date and reason. |
| Automation opportunities | Monthly check-ins, quarterly readiness prompts, renewal reminders, educational content, reactivation campaigns. |
| Human review required | Review tone, opt-out handling, compliance-sensitive claims, and whether continued outreach is appropriate. |
| Common failure point | Good leads rot because nobody built a nurture lane. That is leaving cash flow in the couch cushions. |

**Recommended automation:** Use segmented nurture based on reason lost: timing, documents, revenue, offer declined, unresponsive, or not ready.

---

### 14. Do Not Pursue

| Field | Details |
|---|---|
| Stage definition | The file should not be actively pursued due to unsuitable fit, concerning behavior, duplicate/spam lead, compliance risk, or other broker-reviewed reason. |
| Entry criteria | Broker or manager determines the file should not proceed. |
| Exit criteria | Usually none, unless a manager reopens the file after review. |
| Owner | Broker, compliance reviewer, or agency owner. |
| Next action | Document reason, stop automation where appropriate, and avoid further active solicitation unless approved. |
| Automation opportunities | Suppression tag, stop follow-up sequences, archive tasks, manager notification. |
| Human review required | Required. Do not let automation decide sensitive disqualification alone. |
| Common failure point | Risky files keep getting automated follow-up because nobody killed the sequence. Zombie pipeline, but with liability. |

**Recommended automation:** Apply a suppression tag that stops borrower-facing sequences and requires manager review to reopen.

## Recommended CRM Fields

Use these fields to make the pipeline searchable, filterable, and useful. A CRM without structured fields is just a diary with invoices attached.

| CRM Field | Field Type | Purpose | Notes |
|---|---:|---|---|
| Lead source | Dropdown | Tracks where the lead came from | Examples: website, referral partner, ad, event, cold outreach, existing client. |
| Business name | Text | Identifies borrower business | Keep legal name and DBA separate if needed. |
| Contact name | Text | Primary borrower contact | Include title if relevant. |
| Industry | Dropdown/Text | Helps with lender-fit considerations | Avoid unsupported assumptions based only on industry. |
| Time in business | Number/Dropdown | Supports pre-screening | Use months or years consistently. |
| Monthly revenue | Currency/Range | Supports funding-readiness review | Should be verified against documents where needed. |
| Funding requested | Currency | Captures borrower request | Request is not the same as lender-approved amount. |
| Use of funds | Dropdown/Text | Explains funding purpose | Be specific: inventory, payroll, equipment, marketing, expansion, working capital. |
| Credit range | Dropdown | Soft borrower-provided estimate | Do not treat self-reported credit as verified. |
| Urgency | Dropdown | Prioritizes follow-up | Examples: immediate, 7 days, 30 days, flexible. Avoid fake urgency. |
| Product interest | Dropdown | Tracks expected funding path | Examples: working capital, LOC, term loan, equipment, SBA, business credit, partner program. |
| Missing documents | Multi-select/Text | Drives document follow-up | Keep specific, not vague. |
| Lender submitted to | Multi-select/Text | Tracks lender submissions | Include date and status where possible. |
| Last contact date | Date | Shows recency | Useful for follow-up automation. |
| Next follow-up date | Date | Keeps pipeline moving | Every active deal should have one. |
| File status | Dropdown | Tracks document completeness | Examples: intake needed, docs requested, partial, complete, submitted, funded, nurture. |
| Risk notes | Long text | Captures concerns for broker review | Keep factual, professional, and non-inflammatory. |
| Referral partner | Linked record/Text | Tracks partner source | Enables partner updates and commission workflows. |

## Stage Movement Checklist

Before moving any file forward, confirm:

- [ ] The current CRM stage is accurate.
- [ ] The borrower profile is updated.
- [ ] The funding request is documented.
- [ ] The use of funds is documented.
- [ ] Monthly revenue is captured or marked unknown.
- [ ] Time in business is captured or marked unknown.
- [ ] Missing documents are listed clearly.
- [ ] Last contact date is updated.
- [ ] Next follow-up date is set.
- [ ] The deal has an owner.
- [ ] Any AI-generated summary has been human-reviewed.
- [ ] No borrower-facing communication includes approval promises or unsupported claims.

## Weekly CRM Audit

Run this once per week. It is not glamorous. It is how you stop pipeline rot.

| Audit Question | Action |
|---|---|
| Which active deals have no next follow-up date? | Assign a next action or move to nurture. |
| Which deals have been in the same stage too long? | Review and update status. |
| Which files are missing documents? | Send specific missing-doc follow-up. |
| Which submitted files need lender follow-up? | Create lender status tasks. |
| Which offers need borrower review? | Schedule review call or send approved recap. |
| Which leads should be moved to nurture? | Stop active pursuit and enroll in nurture sequence. |
| Which automations fired incorrectly? | Fix trigger logic and document the issue. |
| Which AI outputs were used? | Confirm human review and audit trail. |

## Broker Safety Note

Funding broker CRM automation should support organization, follow-up, document collection, internal summaries, and workflow visibility. It should not make approval decisions, quote final terms, guarantee funding, replace lender review, or send sensitive borrower communication without human review.

Handle sensitive borrower data carefully. Use secure systems for bank statements, IDs, tax returns, voided checks, debt schedules, bank links, and financial documents. Avoid placing sensitive borrower data into AI tools or automation platforms unless you have appropriate permissions, security controls, and a clear business reason. Consult qualified legal, compliance, tax, or accounting professionals where appropriate.

Use careful language:

- Funding options may be available.
- Eligibility varies.
- Lender review required.
- Approval is not guaranteed.
- Documentation may be required.
- Terms may change.
- Human review required.
